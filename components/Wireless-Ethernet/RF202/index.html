    RF-5V 433MHz Wireless Transceiver Module - RF202¶

    Simple 433MHz wireless transceiver module for point-to-point communication. Features UART interface for serial data transmission over air. Perfect for wireless sensors, remote control, and simple telemetry applications.

    Key Specifications¶

    Parameter Value
    Frequency 433 MHz (ISM band)
    Range ~100m (open air, line-of-sight)
    Interface UART (serial)
    Baud rate Configurable (1200-115200 bps typical)
    Supply voltage 5V DC
    Current ~20mA (RX), ~35mA (TX)
    Modulation ASK/OOK (typical)
    Operating temp -20°C to +70°C

    How It Works¶

    Wireless UART: - Transparent serial passthrough - Data in on TX pin → transmitted over air - Received data → output on RX pin - Like invisible wire between two microcontrollers

    433 MHz ISM band: - License-free frequency - Good penetration through walls - Longer range than 2.4 GHz - Less crowded than WiFi

    Pinout¶

    RF-5V Module
    ___
   |~~~| Antenna
   | R |
   | F |
   |___|
   | | | |
   V G R T
   C N X X
   C D

VCC = Power (5V)
GND = Ground
RX  = Receive data (input to module)
TX  = Transmit data (output from module)

    Some modules also have: 

    EN  = Enable pin (pull HIGH to enable)
SET = Configuration mode pin

    Typical Wiring (ESP32)¶

    MCU             RF-5V
---             -----
5V     -------> VCC
GND    -------> GND
TX     -------> RX (MCU transmits to RF module)
RX     -------> TX (MCU receives from RF module)

    Note: Use level shifter if MCU is 3.3V logic (ESP32 RX is 3.3V tolerant but TX may need shifting to 5V).

    Example Code (ESP32)¶

    // ESP32 + RF-5V Transceiver
// Using Serial2 (GPIO16=RX2, GPIO17=TX2)
#define RXD2 16
#define TXD2 17

void setup() {
  Serial.begin(115200);   // Debug
  Serial2.begin(9600, SERIAL_8N1, RXD2, TXD2);  // RF module

  Serial.println("RF-5V Wireless Ready");
}

void loop() {
  // Send data
  if (Serial.available()) {
    char c = Serial.read();
    Serial2.write(c);  // Transmit over RF
    Serial.print("Sent: ");
    Serial.println(c);
  }

  // Receive data
  if (Serial2.available()) {
    char c = Serial2.read();
    Serial.print("Received: ");
    Serial.println(c);
  }
}

    Wireless Sensor Example¶

    Transmitter (sensor side): 

    void loop() {
  float temperature = 25.3;
  int humidity = 65;

  // Send data packet
  Serial2.print("T:");
  Serial2.print(temperature);
  Serial2.print(",H:");
  Serial2.println(humidity);

  delay(5000);  // Send every 5 seconds
}

    Receiver (base station): 

    void loop() {
  if (Serial2.available()) {
    String data = Serial2.readStringUntil('\n');
    Serial.print("Sensor data: ");
    Serial.println(data);

    // Parse data: "T:25.3,H:65"
    int tIndex = data.indexOf("T:");
    int hIndex = data.indexOf("H:");

    if (tIndex >= 0 && hIndex >= 0) {
      float temp = data.substring(tIndex + 2, hIndex - 1).toFloat();
      int hum = data.substring(hIndex + 2).toInt();

      Serial.printf("Temperature: %.1f°C, Humidity: %d%%\n", temp, hum);
    }
  }
}

    Remote Control Example¶

    Transmitter (remote): 

    #define BUTTON_1 25
#define BUTTON_2 26

void loop() {
  if (digitalRead(BUTTON_1) == LOW) {
    Serial2.println("CMD:LIGHT_ON");
    delay(200);  // Debounce
  }

  if (digitalRead(BUTTON_2) == LOW) {
    Serial2.println("CMD:LIGHT_OFF");
    delay(200);
  }

  delay(50);
}

    Receiver (controller): 

    #define RELAY_PIN 27

void loop() {
  if (Serial2.available()) {
    String cmd = Serial2.readStringUntil('\n');

    if (cmd == "CMD:LIGHT_ON") {
      digitalWrite(RELAY_PIN, HIGH);
      Serial.println("Light turned ON");
    } else if (cmd == "CMD:LIGHT_OFF") {
      digitalWrite(RELAY_PIN, LOW);
      Serial.println("Light turned OFF");
    }
  }
}

    Key Features¶

    Simple UART interface: - Transparent serial passthrough - No complex protocols - Works with any MCU

    Good range: - ~100m line-of-sight - Better than IR - Works through walls

    Low cost: - Very cheap modules - No licensing fees - Easy to source

    Low power: - Good for battery applications - Sleep modes available - Low RX current

    Gotchas¶

    1. 5V only: Module requires 5V power (not 3.3V)
    2. No handshaking: No acknowledgment of received data
    3. Packet loss: RF interference can cause data loss
    4. No error correction: Corrupted data not detected
    5. Half-duplex: Can't transmit and receive simultaneously
    6. Range varies: Obstacles, interference reduce range significantly
    7. Antenna needed: Many modules need external antenna for good range

    Adding Reliability¶

    Simple packet format: 

    void sendPacket(String data) {
  // Add start marker and checksum
  String packet = "<" + data + ">";
  Serial2.println(packet);
}

String receivePacket() {
  static String buffer = "";

  while (Serial2.available()) {
    char c = Serial2.read();
    buffer += c;

    if (c == '>') {  // End marker
      int start = buffer.indexOf('<');
      if (start >= 0) {
        String packet = buffer.substring(start + 1, buffer.length() - 1);
        buffer = "";
        return packet;
      }
    }
  }

  return "";
}

    Configuration¶

    Some modules support AT commands for configuration:

    void setup() {
  Serial2.begin(9600);

  // Enter config mode (varies by module)
  // Pull SET pin LOW or send special command

  // Example AT commands (module-specific):
  Serial2.println("AT+ADDR=01");     // Set address
  Serial2.println("AT+BAUD=4");      // Set baud rate
  Serial2.println("AT+POWER=20");    // Set TX power (dBm)

  delay(500);
}

    Check module datasheet for specific AT commands.

    RF-5V vs WiFi¶

    Feature RF-5V (RF202) WiFi (ESP32)
    Range ~100m ~50-100m
    Setup Simple UART WiFi credentials needed
    Internet No (local only) Yes (via router)
    Power ~20-35mA ~160-260mA
    Cost $1-2 $3-5 (ESP32)
    Data rate Low (kbps) High (Mbps)

    Use RF-5V when: - Simple point-to-point needed - No internet required - Low power critical - Very low cost needed

    Use WiFi when: - Internet connectivity needed - Higher data rate required - Network infrastructure available

    Applications¶

    Wireless sensors: Temperature, humidity, motion sensors without wires.

    Remote control: Control lights, relays, motors wirelessly.

    Telemetry: Send sensor data from remote locations.

    Home automation: Simple wireless control without WiFi.

    Weather station: Outdoor sensor to indoor display.

    Wireless doorbell: Transmitter button to receiver chime.

    Troubleshooting¶

    No communication: - Check baud rate matches both sides - Verify TX/RX not swapped - Check 5V power adequate - Antenna connected?

    Short range: - Add/improve antenna - Check for RF interference - Obstacles blocking signal - Increase TX power (if configurable)

    Corrupted data: - Reduce baud rate - Add error checking (checksums) - Reduce distance - Use packet format with delimiters

    Intermittent connection: - RF interference (try different channel if module supports it) - Power supply unstable - Antenna loose
